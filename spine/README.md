# <PROJECT> Documentation: read this first

This `docs/` tree is the **single source of truth** for <PROJECT>. One tree, four classes of artifact, each maintained differently. The #1 cause of documentation drift is treating all four the same: hand-editing things that should be generated, and copying one fact into many places. Don't.

## The four classes

| Class | Where | Who writes it | When | Rule |
|---|---|---|---|---|
| **CANONICAL** | `docs/*.md` | a human, deliberately | at the moment of a decision | small, single-sourced; the only place a fact is authored |
| **DERIVED** | `docs/derived/*.md` | the `/savepoint` skill | at session end | **NEVER hand-edit** (regenerated from canonical + git) |
| **REFERENCE** | `docs/runbooks/`, `docs/reference/` | a human, occasionally | when a procedure changes | low-drift; not read as "current product truth" |
| **SKILLS** | `.claude/skills/` | a human, when a procedure breaks | on use | runnable procedures that *reference* canonical docs, never restate them |

## The canonical set

| File | Owns (source of truth for) |
|---|---|
| [`PRODUCT.md`](PRODUCT.md) | feature inventory: what exists, status (live / held / deferred / killed), held/deferred list |
| [`FEATURES-PAGES.md`](FEATURES-PAGES.md) | the matrix: feature ↔ route ↔ flow ↔ navigation. **Input to mockup/code generation AND the verification checklist.** |
| [`DECISIONS.md`](DECISIONS.md) | append-only decisions **and removals** (negative knowledge: why a killed feature must not return) |
| [`DESIGN.md`](DESIGN.md) | brand, tokens, components (defers to code) |
| [`ARCHITECTURE-ROADMAP.md`](ARCHITECTURE-ROADMAP.md) | current system map (present tense) + forward plan / horizons (future tense) |
| root `CLAUDE.md` / `AGENTS.md` | agent operating rules (live at repo root) |

Derived: `derived/CHANGELOG.md`, `derived/GAPS.md`, `derived/CONTINUITY.md`, `derived/LESSONS.md` (+ optional `FOUNDER-ACTIONS.md` / owner-actions).

## The rules (these are what prevent drift)

1. **WRITE-ONCE.** A new feature, decision, or removal is authored in exactly **one** canonical place. Everything else *references* it or is *generated* from it. New feature → a `PRODUCT.md` row + a `FEATURES-PAGES.md` row + a `DECISIONS.md` line. Mockups and code derive from those; `CHANGELOG`/`GAPS` record it after the fact.
2. **REMOVALS ARE FIRST-CLASS.** When something is killed, do **not** just delete its row. Flip its `PRODUCT.md` status to `killed` and append a `DECISIONS.md` entry with the rationale. A deleted row is invisible and gets re-added; a `killed` row + decision entry is the negative knowledge that stops resurrection.
3. **NEVER HAND-EDIT A DERIVED DOC.** If you're editing `CHANGELOG`/`GAPS`/`CONTINUITY`/`LESSONS` by hand, that's the bug; they're regenerated by `/savepoint`. The moment you hand-edit one it silently becomes canonical and drifts.
4. **CODE WINS.** The values in code (design tokens, copy strings, route tree, schema) are canonical-by-code. Docs *mirror* them and must never hard-code a contradicting value.
5. **ARCHIVE, NEVER DELETE.** Superseded docs move to `docs/_archive/` with a banner, never deleted. Nothing is lost; the old copy never coexists as competing "live" truth.

## How an update flows
```
new idea / decision / removal
        │
        ▼
  ONE canonical edit  ──►  PRODUCT.md (+status)  ·  FEATURES-PAGES.md (row)  ·  DECISIONS.md (entry)
        │
        ├──►  mockups / generation are GENERATED from FEATURES-PAGES  (can't drop a feature)
        ├──►  code implements it
        └──►  at session end, /savepoint regenerates CHANGELOG / GAPS / CONTINUITY
                          └──►  drift-check flags any doc still describing the old state
```

## Maintenance
- **Canonical** docs are edited by hand, at the moment of decision (small, so cheap).
- **Derived** docs are regenerated by `/savepoint` at session end (run manually first; a `Stop` hook automates it later).
- Installed by [RespawnPack](https://github.com/<you>/RespawnPack).
